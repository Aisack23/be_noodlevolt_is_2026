# feat(BE-02): registrar pedidos para llevar con idempotencia

## Qué cambia

- Se implementa POST /api/v1/orders para clientes autenticados.
- Se valida sucursal, clave de operación, platillos y cantidades.
- El propietario se toma de la sesión; precios históricos y total se calculan en servidor con aritmética decimal.
- Se comprueba sucursal abierta dentro de la transacción y se bloquean los datos relevantes.
- Se responde 201 al crear, 200 al reintentar el mismo contenido y 409 si cambia el contenido o propietario.
- Se persisten total y huella de solicitud con una migración nueva.
- Se registra paymentMode=ONLINE, obligatorio para TAKEOUT en el esquema actual, manteniendo status=PENDING y sin registrar pagos.
- Se añaden pruebas y documentación técnica.

## Qué queda fuera

- Cocina, entrega y notificaciones: sus respectivas tareas.
- Inventario real, frontend y cambios de autenticación.
